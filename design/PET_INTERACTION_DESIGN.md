# 桌宠动画与交互设计 — 情绪价值方案（Pet Interaction Design）

> 版本：2026-09-19 · 状态：待定稿（配套演示页 `design/pet-interaction-demo.html`，动画可交互触发）
> 范围：`src/PetApp.vue` 的动画体系、交互语义、信息密度、情绪曲线。
> 三项要求：**可爱 · 交互带来情绪价值与激励 · 只保留必要的信息**——外加本项目不可让渡的第四项：**注意力友好**。

**一句话立场**：桌宠是**镜子，不是闹钟**。它的情感价值来自「对你每个动作的即时回应」，而不是「需要你照料的责任」——前者是陪伴，后者是注意力税。可爱不靠改精灵（素材是固定 GIF），靠**动画的时机与物理**；激励不靠连击羞耻，靠**捕捉成功的那一刻被认真庆祝**。

## 一、社区最佳实践调研 → 本项目的转译

| 来源 | 社区/学术结论 | 本项目转译 |
|---|---|---|
| Tamagotchi 效应（[Yukai Chou](https://yukaichou.com)、[学术综述](https://www.sciencedirect.com)） | 「照料责任」是虚拟宠物留存的王牌——宠物会饿、会死，用户因责任而依恋 | **不采用**。责任机制 = 宠物向用户收注意力税，违反 README 原则 1/6（默认安静、不制造羞耻）。本项目宠物的「需求」只有一个：跟你的工作走 |
| Clippy 悲剧（[Mental Floss](https://www.mentalfloss.com)、[UX StackExchange](https://ux.stackexchange.com)） | 助手被恨的三要素：太主动、太泛、打断你正在做的事 | **三不原则**：不主动开口（除用户设定的事件）、不打断（所有演出是用户动作的回应）、不废话（气泡一屏一义）。现状已守住，成文为红线 |
| Duolingo 猫头鹰（[Lippincott](https://www.lippincott.com)） | 吉祥物人格 + 连击/损失厌恶 = 病毒式留存，也是内疚式设计的老巢 | **只取人格，不取内疚**。宠物的「催」只存在于文案语气（急得直跺脚），永不绑定损失机制；没有 streak 断裂惩罚，只有捕捉成功的庆祝 |
| Juice 框架（[GDC: Juice It or Lose It](https://gdcvault.com)、[Brad Woods](https://garden.bradwoods.io)） | 「多汁」= 每个元素被触摸时会弹会晃，**预备→动作→回应**三段式；游戏手感来自缓动与过冲，不来自玩法 | **全盘采用为动效语法**。完成一个任务要有 1.5 秒的捕捉演出，而不是打勾消失。所有事件动画按 预备(蹲)→动作(掷球)→回应(星星) 编排 |
| 幼态 Schema（[UX Design: Baby Schema in UX](https://uxdesign.cc)、[ScienceDirect 2023](https://www.sciencedirect.com)） | 大头身、圆形状、简化的脸触发照料本能 | 精灵是固定 GIF 改不了，**可爱转移到三处**：①动画时机（squash & stretch、过冲回弹、不对称小幅度）②气泡与药丸的圆角软形状（已有）③文案的幼态语气（已有）。像素风的「变形代替表情」是 GB 时代正统：眨眼=压扁、哈欠=拉长 |
| 桌面宠物研究（[Edward Yi 2025](https://edwardyi.me)、[Nathalie Lawhead](https://www.nathalielawhead.com)、Shimeji 生态） | 桌宠提升情绪与陪伴感的核心是**低风险在场 + 微妙的生命感 + 可定制**；Shimeji 长盛不衰靠随机小动作和「它在过自己的日子」 | **生命感调度器**：idle 时低频随机小动作（眨眼/左右看/翻面/哈欠），像它自己在过日子；**可定制已有**（1025 只换装 + 每只自定义台词） |

## 二、设计立场：四条原则

1. **回应，不打扰**——所有演出（庆祝、问候、提醒）都是用户动作或用户设定事件的直接回应；宠物永不自发索要注意力。演出期间任意点击可跳过。
2. **动效即信息 + 生命感豁免**——README 原则 4（循环动画只用于传达状态）细化为两档：**信息动画**（进行中跳跃、紧急抖动、色环）维持原纪律；**生命微动作**（眨眼、左右看）属于「它活着」这一状态本身，允许低频存在，但受调度器约束（§4.4）且跟随减弱动效开关。
3. **激励只有正反馈**——庆祝强度分级（普通捕捉/里程碑/收工），没有损失、没有羞耻、没有「宠物失望了」。
4. **一屏一义**——对话框同时只说一件事；常驻元素每个都要挣自己的位置（§5 信息极简）。

## 三、情绪设计总纲：三层情绪价值 × 一天的陪伴节奏

**三层情绪价值**（由浅入深）：

| 层 | 机制 | 例 |
|---|---|---|
| L1 即时反馈 | 每个操作 100ms 内有可感回应（juice） | 按下有按压位移、撸宠有弹跳、拖拽有悬挂物理 |
| L2 状态陪伴 | 宠物形象 = 你的工作状态的镜子 | 专注时它蹦跳陪跑、暂停变灰打盹、尾段它比你还急 |
| L3 成长记忆 | 完成与里程碑被「郑重对待」 | 捕捉演出、图鉴 +1、累计捕捉贺词、收工晚安 |

**一天的陪伴节奏**（全部被动触发，无主动打扰）：

```
晨间首现 ──→ 工作陪伴 ──→ 捕捉庆祝(×N) ──→ 收工演出 ───→ 睡觉
时段问候      专注/暂停/焦急    掷球三摇星星     今日图鉴圆满    系统闲置 zzz
```

- **时段问候**：每天窗口首次出现说一次（早/午/晚三档文案 + 主宝可梦名，i18n 已有 quotesNight 池可扩展）；只此一次，绝不重复。
- **睡觉**：系统输入闲置 ≥5 分钟（或用户从图鉴机收起后）→ 呼吸缩放 ±2% + zzz 气泡 + 轻灰度；任何输入（移动到精灵上/点击）→ 揉眼醒来（伸展 + 打招呼）。「你回来了」是零成本的高情绪时刻。

## 四、动画规范 v2

### 4.1 动效令牌（补进 dex.css，与设计系统焕新方案同源）

```css
:root {
  /* 时长档 */
  --t-tap: 80ms;      /* 按压反馈 */
  --t-pop: 150ms;     /* 微动作单程（眨眼、抖动一帧） */
  --t-act: 300ms;     /* 事件动作单段（掷球、跳一下） */
  --t-scene: 600ms;   /* 演出单段（球摇一轮、落地回弹） */
  /* 缓动档（可爱=过冲与挤压，禁用匀速） */
  --e-pop: cubic-bezier(.34,1.56,.64,1);   /* 弹出过冲（回弹感） */
  --e-snap: cubic-bezier(.2,.9,.3,1.2);    /* 快落轻过冲 */
  --e-sway: cubic-bezier(.45,0,.55,1);     /* 摇摆往返（对称舒缓） */
  --e-sleep: cubic-bezier(.4,0,.6,1);      /* 呼吸（慢对称） */
  /* 幅度档 */
  --a-micro: 3px;  --a-hop: 7px;  --a-burst: 12px;
}
```

**可爱三律**（固定 GIF 上的动画层语法）：①落地必挤压（scaleY .85 → 回弹 1.05 → 1）；②过冲必回弹（位移/缩放用 --e-pop，不用 ease）；③动作带预备帧（跳之前 80ms 蹲一下）。现有 `pk-hop` / `pk-petted` 已部分符合，缺预备帧与落地挤压。

### 4.2 状态机扩展

```
idle ──┬─ idle.calm（默认，慢呼吸+微动作池）
       ├─ idle.bored（无任务且闲置 >10min，微动作频率+，偶尔看向图鉴机方向）
       └─ asleep（系统闲置 ≥5min，zzz）
working（蹦跳主循环，微动作池降频）
paused（灰度+慢呼吸，不打盹到 sleep）
urgent（抖动，占用同屏唯一闪烁名额）
celebrating（捕捉演出，独占，1.5s 上限）
petting（撸宠，0.9s，可被打断）
dragging（拖拽悬挂物理）
```

### 4.3 事件演出编排（juice 三段式）

**★ 捕捉成功演出（核心品牌时刻，产品名就来自这句台词）**——总时长 ≤1.5s，点击可跳过：

| 段 | 时长 | 画面 |
|---|---|---|
| 预备 | 120ms | 点 ✔ → 精灵蹲下（scale .9），对话框收起，一个精灵球图标在对话框位置出现并蓄力下压 |
| 动作 | 300ms | 精灵球抛物线飞向精灵（CSS 抛物线：X 匀速 + Y 用 --e-pop）；精灵 opacity→0 |
| 高潮 | 600ms | 球落地挤压回弹，**摇三摇**（rotate ±14°，三轮，初代捕捉的经典节拍） |
| 回应 | 300ms | 咔哒——星星粒子爆开（4~6 颗，--a-burst 散射）+ 气泡「✔ 捕捉成功！记入图鉴」+ 换下一只精灵（若有） |

演出同时「图鉴 +1」由气泡文字承载，不加常驻元素。里程碑（累计 10/50/100…）升级为双排星星 + 贺词；**收工演出**（今日任务清零）再加一跳 + 「今日图鉴圆满，收工！」，仅此一次。

**问候/醒来/就寝**：均为「一段微演出 + 一句话气泡」（伸展 300ms / 揉眼 300ms / 呼吸渐弱 600ms），无粒子。

**拖拽物理**：拖动中精灵跟随但有 8° 倾斜 + 轻微滞后（跟随点在脚下，头甩动）；松手落定挤压回弹一次。让「拎着它走」本身好玩。

### 4.4 生命感调度器（idle 微动作池）

| 微动作 | 实现（GIF 变形魔法） | 权重 | idle.calm 频率 |
|---|---|---|---|
| 眨眼 | scaleY(0.15) 120ms | 5 | 常驻，8~15s 随机 |
| 左右看 | translateX ±4px + rotate ∓2°，停 400ms 看另一侧再回 | 3 | 20~40s 随机 |
| 翻面 | scaleX(-1) 600ms 后翻回（好奇地转身） | 2 | 60~120s 随机 |
| 哈欠伸懒腰 | scaleY(1.12)+translateY(2px) 慢起慢落 900ms | 1 | 3~6min 随机 |

规则：**working 态只保留眨眼且频率减半**（专注时不打扰）；同一时间只有一个微动作；与事件演出互斥；`prefers-reduced-motion` / 应用内开关直接全关（现有双通道机制复用）。这解决「循环动画只用于传达状态」与「生命感」的张力——微动作是受调度的离散事件，不是循环，且永远静音。

### 4.5 闪烁名额管理

现状对话框右下 ▼ 以 1Hz 永久闪烁，占掉了「同屏唯一闪烁」名额，紧急提醒来时出现双闪烁。改为：**▼ 默认静态**（存在即语义），仅当气泡为「未读新事件」（提醒/庆祝）时闪 3 次后停——闪烁回归「有新事」的信号本义。

## 五、信息极简：桌宠元素审计

现状常驻元素：精灵、色环、cat-tag（分类·宝可梦）、对话框、番茄药丸（5 钮）、（条件）提醒动作条、快捷屏、切换浮层。逐项裁决：

| 元素 | 裁决 | 理由 |
|---|---|---|
| 精灵 | **保留**，核心 | 情绪载体 |
| 色环 | **保留全程** | 时间盲友好是刚需（被动信号原则）；已是 SVG 细环不打扰 |
| cat-tag 常驻标签 | **移除常驻** → 并入开始任务时的开场气泡说一次（「皮卡丘接下了『周报』！」），此后精灵图即分类 | 分类是低频信息，常驻标签是纯视觉税；-1 元素 |
| 对话框 | **保留**，一屏一义 | 气泡同时只承载一件事（状态/事件台词二者其一），提醒来时台词+动作条成对出现 |
| 药丸 5 钮（⏸ ▶ 🍦 ✔ ⇄） | **收敛为 2+上下文**：运行中只显示 ⏸ ✔；暂停态显示 ▶ 🍦 ✔；**⇄ 切换移入右键菜单** | 换目标是低频操作；主操作 ≥2 时刻保持大目标；-1 常驻按钮 |
| 提醒动作条 | **保留**（已有 ✔/⇨ 就近出口） | 消化「提醒→完成」流失链路，是信息不是噪音 |
| 今日进度 | **不加常驻元素**，进晨间问候（「昨天捕捉 3 只，今天草丛里还有 2 只」） | 需要时问一句，平时不占屏 |
| 里程碑/连击 | **不加数字角标**，只做一次性演出 + 图鉴机内贺词 | 激励走 L3 记忆层，不走常驻 UI |

极简后的桌宠静景：**精灵 + 色环 + 一句话对话框 + 2 钮药丸**——四个元素，各挣到了自己的位置。

## 六、交互语义表（v2）

| 手势 | 现状 | v2 | 情绪价值点 |
|---|---|---|---|
| 单击精灵 | 开/关快捷屏 | 不变，但展开前先播 150ms 跳一下（回应感） | 「它知道你点了它」 |
| 双击精灵 | 打开图鉴机 | 不变 | — |
| 右键 | 菜单（4 项） | +⇄ 切换目标；菜单项保持 ≤5 | 收纳低频 |
| **按住 ≥600ms** | 无（长按拖拽冲突） | **撸宠专用入口**：不打开任何面板，纯弹跳+台词（现在撸宠混在单击里随机触发） | 无副作用的纯情绪交互，猫撸狗吸的桌面版 |
| 拖拽 | 平移 | +悬挂物理（§4.3） | 拎着走的趣味 |
| 拖拽期间 | — | 微动作暂停，精灵「紧张小碎步」姿态（快速小幅摆动） | 它知道自己在被拎着 |
| 快捷屏内 ↑↓+Enter | — | 补键盘流（与收音机一致） | 键盘用户不开面板也能切换目标 |
| 演出进行中点击 | — | 跳过演出 | 永不绑架用户时间 |

> 长按与拖拽的冲突处理：mousedown 后 600ms 内未移动超 4px 判定为长按（触发撸宠并取消拖拽预备）；一旦超阈值进入拖拽则不再触发。现有 `usePetDrag` 加一个「未移动的按下」分支即可。

## 七、落地路线

| 阶段 | 内容 | 规模 |
|---|---|---|
| **P0 定稿** | 本方案 + 演示页过目；确认捕捉演出时序、微动作池、信息极简三项裁决 | 文档 |
| **P1 动效基建** | 动效令牌入 dex.css；pk-hop/pk-petted 升级（预备帧+落地挤压）；▼ 静态化；拖拽物理 | 纯 CSS + 少量 JS，1~2 天 |
| **P1 生命感调度器** | 微动作池 + 随机调度 + 状态互斥 + reduced-motion 全关 | composable `usePetIdle`，1 天 |
| **P2 捕捉演出** | 精灵球三摇 + 星星粒子 + 跳过；里程碑/收工分级 | 1~2 天 |
| **P2 信息极简** | cat-tag 并气泡、药丸收敛 2+上下文、⇄ 入右键 | 0.5 天 |
| **P3 睡眠与问候** | 系统 idle 检测、醒来/问候/就寝微演出、晨间进度问候 | 1 天 |

验收红线（每阶段回归）：同屏闪烁 ≤1、演出 ≤1.5s 且可跳过、所有新动画跟随减弱动效双通道、桌宠静景 ≤4 元素。
