# 桌宠体验升级方案 —— 输入响应 · 对话 · 时间与空间感知

> 目标：在既有「镜子不是闹钟」体系（[PET_INTERACTION_DESIGN](../design/PET_INTERACTION_DESIGN.md)）之上补齐**环境感知层**——
> 让桌宠感知得到「你正在打字」「现在几点」「它站在屏幕的哪里」，并让任务数据**可对话**。
> 调研时间：2026-09-20（社区桌宠交互调研：VPet / Shimeji / Bongo Cat / Desktop Goose / Desktop Mate / koi-pond，结论见 §2）。
>
> **实施状态**：M1–M3 已全部落地（2026-09-20）。
> - M1 纯前端：F4 栖息（`usePerch` + 拖拽落点判定，动画幅度减半）、F3 时刻台词（`useTimeLines`，
>   localStorage 每类每周期去重，urgent/提醒/对话态让路）、F7 连胜演出（`task_streak` 命令 +
>   双球交替三摇变体，里程碑优先）、F6 陪跑精灵（`dex_stats.sprites` 候选池，一次会话一位一次）。
> - M2 输入链路：F1（`input.rs` rdev 监听线程只计数、每秒 `emit_to("pet")`；macOS
>   `AXIsProcessTrusted` 检查 + 设置页授权提示 + 拒绝回落；前端 `useInputResponse` 分档）。
> - M3 外部服务：F2 对话（`pet_chat` 命令接 `run_agent` + 任务上下文 prompt + 两句收敛，
>   桌宠右键菜单入口、对话框原位对话态）、F5 语音（`voice.rs` 平台系统 TTS：macOS `say` /
>   Windows System.Speech / Linux spd-say→espeak，四类时刻接线；**EdgeTTS 云引擎档未实施**，
>   保持「显式选择 + 云服务提示」的要求留作后续）。
> - 与方案的差异：连胜口径实现为「连续有捕捉的日历日 + 一个宽容日、今天未捕捉不清零」（周口径的
>   判定基础，触发阈值 ≥3 天且当日首捕）；事件契约新增 `input-activity`（两侧契约测试同步）。
> 配套可交互设计稿：[pet-experience-demo.html](../design/pet-experience-demo.html)。
> 明确不做（ROADMAP「明确暂不做」）：任务养成闭环（亲密度/EXP/喂食/心情体力）、常驻数值面板、Shimeji 式破坏行为。

## 一、现状与缺口

现有体系已覆盖三层情绪价值的前两层：L1 即时反馈（点击/撸宠/拖拽物理）、L2 状态陪伴（五态状态机 + 倒计时色环 + 尾段焦急）、L3 成长记忆（捕捉演出 + 里程碑 + 收工）。缺口集中在**环境感知**——桌宠只看得见「发生在它面前的操作」，看不见你这一天：

| # | 缺口 | 现状 | 社区参照 |
|---|---|---|---|
| G1 | 感知不到打字 | 只有指针点到精灵本体才有反应 | Bongo Cat：仅凭「对输入的实时反应」一点即病毒式传播，是生命感最强来源 |
| G2 | 任务数据不可问 | 「今天还剩什么」必须开主面板 | Desktop Mate 社区呼声第一的功能是 AI 对话；本项目有 agent 基建的独特优势 |
| G3 | 时间感知单薄 | 仅时段问候四档（早/午/晚/深夜） | VPet 时钟插件；深夜/纪念日是高情绪时刻 |
| G4 | 无空间行为 | 悬空站立，拖到哪停哪 | Shimeji 的边缘栖息可信感强（攀爬/扔窗口不做） |
| G5 | 全静音 | 里程碑与收工只有视觉 | VPet 语音插件验证过「一两句」的价值 |
| G6 | 长专注只有一只精灵 | — | body doubling 实证（NPR 2024）：陪伴存在对专注尤其 ADHD 人群显著有效 |

## 二、社区调研结论（要点）

| 项目 | 流派 | 对本方案的直接启发 |
|---|---|---|
| Bongo Cat | 输入响应系 | 对输入的实时反应是生命感最强来源（F1） |
| VPet（LorisYounger） | 养成陪伴系 | 语音（EdgeTTS 插件先例）、时钟（时间感知 F3）；其养成/心情数值**不学** |
| Shimeji | 顽皮破坏系 | 边缘栖息的可信感（F4）；破坏行为被大量卸载的教训——克制 |
| Desktop Mate | 高品质模型系 | AI 对话是社区呼声第一（F2）；Live2D 已在「暂不做」（CPU 负担） |
| koi-pond（CrabNebula/Tauri） | 技术参考 | Rust 侧全局输入事件 → emit 给前端的链路（F1） |

三条共识约束设计：**生命感三层缺一不可**（微动作/输入反馈/系统事件）；**强打扰行为必须 opt-in**（社区用卸载率换来的教训）；**陪伴 ≠ 照料**（本项目立场，与 Finch 模式一致）。

## 三、设计原则

延续 PET_INTERACTION_DESIGN 四原则（回应不打扰 / 动效即信息 / 只有正反馈 / 一屏一义），新增三条针对环境感知的边界：

1. **感知不窥探**：全局输入只产生「活动强度」事件（每秒一次 `{cps}` 计数），永不携带按键内容、窗口标题、应用名；键盘与鼠标合并计数，无法反推输入了什么。
2. **新能力默认关**：所有新增能力（输入响应、语音、陪跑精灵）默认关闭，设置中心 opt-in；AI 对话入口跟随既有 agent 配置出现，不新增配置负担。
3. **演出零数值**：所有新演出不引入常驻数字、进度条、角标——连胜贺词由气泡文字承载一次（与 §4 信息极简一致）。

## 四、功能设计

### F1 输入响应（Bongo Cat 模式）· P0

**问题**：打字是用户在桌宠视野外最高频的活动，桌宠对此零感知——生命感缺了最强的一层。

**交互设计**（响应分四档，全部为「跟随」而非「演出」——幅度 ≤`--a-micro`，无音效、无气泡、不占闪烁名额）：

| 输入强度（键鼠事件/秒） | idle / paused 态 | working 态 |
|---|---|---|
| <2 静默 | 无反应 | 无反应 |
| 2~5 轻打字 | 微抖回应：±2° 快速小幅摆动 120ms，每 2~4s 至多一次 | hop 主循环频率轻度耦合（+0~10%，打字越快蹦得越欢） |
| 5~10 密集 | 「认真看」：停一拍 + 看向屏幕（微动作 look 复用） | hop 耦合上限 +10%，微抖回应继续 |
| 停顿 >3s | 一次哈欠或回头看你（池内随机） | 无（不打断专注节奏） |

停止打字 10s 后回到静默档。**纪律**：这是对用户动作的被动跟随（L1），不是自发演出——working 态开启的是「节奏耦合」而非新动画，`减弱动效` 下整体关闭。

**技术方案**：Rust 侧独立线程 `rdev::listen`（键鼠统一回调），回调内只递增计数器，每 1s emit `input-activity { cps }`；`macOS` 需辅助功能权限——开关开启时 `AXIsProcessTrusted` 检查，未授权弹引导（系统设置路径），拒绝则开关回落并保留设置；Windows/Linux 无需权限。前端 `useInputResponse(cps)` 纯函数分档（可测），只读 cps，无任何回传。

**设置**：`桌宠 → 输入响应`（默认关）+ 子项 `专注时也响应`（默认关，独立于主开关）。开关说明文案写明「只感知打字快慢，不知道你打了什么」。

### F2 AI 对话气泡 · P0

**问题**：任务数据只单向展示。想问「今天还剩什么」「这周捕捉了多少」必须开主面板——而本项目有 pk/agent 基建的独家优势。

**交互设计**：
- **入口**：右键菜单新增「💬 和精灵聊聊」（低频入口，不加常驻按钮——静景 ≤4 元素不破）；未配置 agent 时菜单项不出现，零配置负担。
- **形态**：对话框原位进入**对话态**——高度展开至 ≤4 行（最近一条回答 + 三点思考指示 + 输入行），不弹新窗、不脱离桌宠语境；Esc / 点外部 / ✕ 收起，恢复原状态文案。对话态中精灵切「侧耳倾听」微姿态（lean 2°）。
- **回答节奏**：agent CLI 是秒级延迟，这是特性不是缺陷——发送后精灵「歪头思考」（三点跳动 ≤5s 上限），回答到达时气泡 `is-new` 闪三下（复用闪烁规则）。
- **人格与边界**：system prompt 注入精灵人格（宝可梦视角、≤2 句、不指责、词汇表同 COPYWRITING）+ `pk context` 任务上下文（今日剩余/本周图鉴统计）；**只答不执行**——涉及操作的建议带「去主面板确认」出口，不直接改数据。v1 无记忆（多轮记忆留待 [MEMORY_KNOWLEDGE_PROPOSAL](MEMORY_KNOWLEDGE_PROPOSAL.md)）。

**技术方案**：复用 `ai.rs run_agent`（含 SSH 远程通道），单轮调用 `pk context` 拼装 prompt；超时 15s 优雅失败（「精灵在草丛里迷路了，再问一次试试」）；对话记录不落库（仅 debug 日志，遵循「感知不窥探」同款隐私纪律）。

**设置**：无新开关——入口跟随 agent 配置（配了即有，与「集成诊断不做世界观化」不冲突：这是桌宠功能，保持宝可梦视角）。

### F3 时间感知台词 · P1

**问题**：时段问候只有四档，「现在几点」这个最日常的环境信号没有参与陪伴。

**设计**：在时段问候之上新增**时刻台词池**，每类每天最多一次（复用 `greetOnce` 去重机制），全部被动触发、语气遵守「永远不指责」：

| 时刻 | 触发 | 台词示例（宝可梦视角） |
|---|---|---|
| 整点 | 工作时段内整点（9:00~18:00） | 「🐾 {t} 这个小时也要加油哦」 |
| 深夜 | 23:00 后首次交互 | 「这么晚了还在冒险……收工也是很强的选择哦」 |
| 周五晚 | 周五 18:00 后 | 「🐾 路线上的宝可梦都说：周末快乐！」 |
| 精灵生日 | 应用首次启动纪念日当天 | 「今天是 {p} 跟着训练家的第 N 天！」+ 一跳演出 |

深夜台词只提供「收工出口」绝不催睡；生日 = 图鉴首次捕捉日期或首启日（取更早者）。

**技术**：纯前端定时器 + 既有 `say()`；i18n 三语同步。

### F4 屏幕边缘栖息 · P1

**问题**：精灵永远悬空站立，拖到哪站哪——「栖息」比「悬空」可信。

**设计**：拖拽松手时判定落点——距**屏幕工作区底缘 ≤72px**（Windows 任务栏 / macOS Dock 上沿一带）→ 进入栖息姿态：重心下沉（scaleY .92 + translateY 4px 落定回弹一次），此后呼吸幅度减半、hop 类动作幅度减半（它坐着）；拖离底缘自动恢复站立。栖息不改变状态机语义（idle/working 皆可栖息，working+栖息 = 「坐着陪你打字」）。

**不做**：攀爬侧边缘、扒窗口、任何窗口交互（红线）。**技术**：纯前端——`currentMonitor()` 工作区高度 + 拖拽 end 落点判定（纯函数可测）。

### F5 语音 · P2

**问题**：里程碑与收工的「郑重感」只有视觉一层。

**设计**：只在四类时刻发声——里程碑贺词、收工演出、精灵生日问候、AI 对话回答；每次 ≤1 句，音量跟随系统，**默认静音**。语音不伴随任何额外视觉闪烁（不占名额）。

**技术**：首选**本地系统 TTS**（`tts` crate：macOS AVSpeech / Windows SAPI / Linux speech-dispatcher）——零网络、零成本、与本地优先一致；EdgeTTS（云，音质更好）作为显式可选档，选择时设置页注明「语音文本将发往微软云服务」。发音人固定一个（不开放设置项轰炸，v1 只有一个总开关）。

### F6 陪跑精灵（body doubling）· P2

**问题**：长专注会话中只有一只精灵——而「旁边有个存在」对专注有实证帮助（NPR 2024 body doubling 报道，ADHD 人群尤为显著）。

**设计**：专注会话 ≥25 分钟时，一位**客人**从屏幕侧缘走入：图鉴中随机一只已捕捉精灵（排除当前、排除主宝可梦；图鉴为空回退伊布），走到主精灵身旁**坐下**（栖息姿态），安静陪伴到会话结束——结束瞬间随主精灵一起庆祝（收工演出双跳）。用户中途碰它 → 挥手（翻面）离开，不打扰第二次。

**纪律**：一次会话最多一位、只出现一次；它**永远不说话、不闪烁、不加任何常驻元素**——是「临时的客人」不是新成员；`减弱动效` 下跳过走入动画直接就位。**零数值**：它的出现不产生任何统计。

**技术**：第二 `<PokemonSprite>` 影子实体，不进主状态机；触发由 `usePomodoro` 会话时长驱动（纯前端）。

### F7 连胜捕捉演出 · P1

**问题**：连胜（周连胜 + 宽容日，口径见 ROADMAP）达成时，现有单球演出配不上这个时刻。

**设计**：连胜达成日的首次捕捉升级为**双球交替**：两只精灵球交替三摇（A 摇 B 静，交替 3 轮，各 400ms）→ 双排星星 → 贺词「🐾 连胜 N 天！本周的草丛都被你踏平啦！」。总时长 ≤2s（比标准 1.5s 略宽——双球是唯一例外），可跳过，无角标无计数 UI。实现上是 `runCatchScene` 的 `streak` 变体，复用既有演出编排。

## 五、状态机与既有机制的整合

**不新增顶层状态**——所有新能力以三种非状态形态挂进既有体系：

```
idle ─┬─ idle.calm / idle.bored / asleep          （不变）
working（hop 频率可随 cps 轻度耦合，+10% 封顶）      （F1）
paused / urgent / celebrating / petting / dragging （不变）

[姿态修饰 *-perch]   栖息：可叠加于 idle/paused/working，动画幅度减半     （F4）
[调度器外部加权]     输入响应：usePetIdle 之外的第二信号源，受同一 busy 互斥（F1）
[影子实体]           陪跑精灵：独立组件，不进主状态机                      （F6）
[对话框功能态]       chat：对话框的展开形态，非精灵状态                     （F2）
```

## 六、设置中心与 i18n

设置 → 桌宠（新增分组「陪伴」，全部受「减弱动效」联动）：

| 开关 | 默认 | 说明 |
|---|---|---|
| 输入响应 | 关 | 「只感知打字快慢，不知道你打了什么」 |
| └ 专注时也响应 | 关 | working 态的节奏耦合 |
| 桌宠语音 | 关（静音） | 引擎默认系统语音；EdgeTTS 需显式选择并提示云服务 |
| 陪跑精灵 | 关 | 长专注时的客人 |
| AI 对话 | 无开关 | 入口跟随 agent 配置自动出现 |

i18n 新增 key 族 `pet.typing.* / pet.chat.* / pet.timesay.* / pet.voice.* / pet.mate.* / pet.streakN.*`——**三语同批**（zh-Hans / zh-Hant / en），e2e mock（`e2e/tauri-mock.ts`）与测试断言同步（COPYWRITING「三语同步」纪律）。

## 七、实施拆分

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| **M1 纯前端** | F4 栖息、F3 时间台词、F7 连胜演出、F6 陪跑精灵 | 无新依赖，`usePomodoro`/`runCatchScene` 现成 |
| **M2 Rust 输入链路** | F1 输入响应（rdev 线程 + macOS 权限引导 + 降级） | rdev crate；权限链路三平台验证 |
| **M3 外部服务** | F2 AI 对话（run_agent 通道 + prompt 模板）、F5 语音（tts crate，EdgeTTS 可选档） | agent 配置；tts crate |

每个里程碑独立可发布；M2 权限被拒时不影响 M1/M3。

## 八、验收要点

| 功能 | 验收 |
|---|---|
| F1 | 分档纯函数单测（cps 档位表）；working 耦合幅度 ≤+10%；权限拒绝→开关回落；审计点：事件 payload 仅 `{cps}`，无键值/无窗口信息出现在任何日志 |
| F2 | 未配 agent 无入口；回答 ≤2 句且不执行操作；超时文案；Esc 恢复状态文案；对话不落库 |
| F3 | 每类台词每天仅一次（去重单测）；深夜台词无指责词（文案 review 点） |
| F4 | 落点判定纯函数单测；栖息态呼吸/hop 幅度减半；拖离恢复 |
| F5 | 默认静音；发声不伴随新闪烁；EdgeTTS 选择时云服务提示可见 |
| F6 | 一次会话最多一位且一次；客人零台词零闪烁；`减弱动效` 直接就位 |
| F7 | ≤2s 可跳过；无角标；连胜判定失败时静默回落普通演出 |

测试形态沿用 `usePetIdle.spec` 模式：分档/判定抽纯函数（`useInputResponse` / `usePerch`），组件层测生命周期与互斥。
