# 会话过滤偏好——飞书免打扰降级为默认值，用户可在应用内逐会话接管

> brainstorming 方向性设计记录。需求语义与管理范围已与用户确认（2026-09-23）：
> ① 跟随 + 手动覆盖（未触碰会话继续实时跟随飞书免打扰，手动设置后以本应用为准）
> ② 管理范围覆盖所有会话（群聊 + 单聊）。

## 1. 问题理解

**要解决什么**：飞书消息拉取的会话过滤目前完全由飞书侧「免打扰」设置决定——`muted_chat_ids` 每轮查询飞书 API 后 `chats.retain` 将免打扰会话整会话跳过（一条消息都不拉、连上下文都不留）。用户无法在本应用内对单个会话放行或屏蔽，想改变行为只能去飞书客户端改免打扰。

**谁**：使用飞书集成（收音机功能）的桌宠应用用户。

**为什么**：免打扰只是「折叠/噪音会话」的代理信号，存在双向假信号——

- 假阳性：用户为了免通知而 mute 重要单聊/群（常见操作），消息在本应用静默消失。`docs/proposals/FEISHU_MESSAGE_ANALYSIS.md` §9.2 风险 3 已明确点名此痛点。
- 假阴性：用户想在飞书免打扰某群（不要通知），但仍希望本应用收它的消息，做不到。

`docs/proposals/FEISHU_MESSAGE_ANALYSIS.md` §9.3 演进方向已规划「会话级过滤名单替代免打扰启发式，成为一等公民设置」，本特性即落地此事。

**Success criteria**：

1. 用户可在本应用内逐会话查看与设置过滤偏好，三态：**跟随免打扰（默认）/ 总是过滤 / 总是拉取**。
2. 从未手动设置的会话，过滤行为与现状完全一致（实时跟随飞书免打扰，含查询失败降级为不过滤的现状语义）。
3. 手动设置过的会话，过滤决策只看本应用设置；飞书侧后续修改免打扰不影响该会话。
4. 管理范围覆盖所有会话类型（群聊 + 单聊），与现状免打扰过滤不分会话类型的行为对齐。
5. 「总是拉取」的会话重新进入拉取与 AI 判定管线（不再整会话跳过）。

## 2. 关键约束

- 单机 Tauri 应用，SQLite 持久化；迁移采用基线式 `SCHEMA_V1`（只改基线，见 `db.rs` 约定）。
- 免打扰状态只能经 lark-cli 批量查询 API 获得，当前每轮轮询已查询一次；数据源不可旁路。
- 过滤发生在**拉取侧**（整会话跳过），不是展示侧——「总是拉取」意味着该会话重新进入消息拉取、判重、AI 判定全管线。
- 前端设置体系：settings 键值表 + Pinia store + 三语 i18n（zh-Hans / zh-Hant / en，有键位对齐测试）；目前**没有**把会话列表暴露给前端的 command，属新增契约面。
- 会话列表含 chat_id 与真实会话名——`chat_messages` 本就直通前端这些字段，新增暴露不扩大敏感面，但需延续现有假名化策略（真名不进大模型）不回退。
- 文档同步义务：`USER_GUIDE.md`「去飞书设免打扰」引导、`ROADMAP.md`、`proposals/FEISHU_MESSAGE_ANALYSIS.md` §9.2/§9.3 需随实现更新。

## 3. 方案探索（方向性选型）

需求澄清阶段已对两个方向性问题做出选型（用户确认），不再展开备选方案堆砌：

- **过滤语义：跟随 + 手动覆盖**（tri-state），否决「一次性快照」（两态）。理由：未触碰会话零行为迁移（与现状完全一致，无迁移成本）；贴合现有轮询链路（每轮已查免打扰，只需在决策点合并覆盖名单）；用户意图显式锁定，心智模型为「默认不动，想改哪个改哪个」。
- **管理范围：所有会话**，否决「仅群聊」。理由：现状免打扰过滤本就不分会话类型；单聊被免打扰误杀恰是 §9.2 风险 3 的原始痛点，更需要可解救。

## 4. 待落地清单（交给 SDD / AD / UIUX 的开放项）

- [SDD] 三态偏好的用户故事与验收：跟随态下免打扰查询失败的降级语义（维持现状「降级为不过滤」还是收紧）；「总是拉取」会话从过滤态切回时，历史消息窗口如何处理（从当前增量继续 vs 回补窗口）；跟随态与覆盖态在 UI 中如何呈现差异。
- [AD] 过滤偏好的持久化形态：新表 vs settings JSON 键；基线迁移的改法。
- [AD] 会话列表暴露契约：新增 command 的返回结构（chat_id / 名称 / 类型 / 当前生效过滤状态及其来源）；数据源取实时 lark-cli 会话列表、库内已知会话还是合并视图。
- [AD] 过滤决策点的合并逻辑落位（`muted_chat_ids` 与覆盖名单在拉取管线中的合并次序与优先级）。
- [UIUX] 管理入口与形态：设置页飞书区块内 vs 收音机页会话分组快捷开关 vs 双入口；长会话列表的组织（搜索/分组/只显示免打扰会话）；三态控件的呈现。
- [AD + UIUX 契约收敛] 偏好读写的接口面（逐会话设置 / 重置为跟随）与前端状态管理接入方式。
- 文档与 i18n 三语同步清单。
